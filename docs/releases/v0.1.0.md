# InkClerk v0.1.0 — Claude Plug-in

**Released:** 2026-07-31

This is InkClerk's first release: a Claude Code plugin and MCP server that brings the
draft/accept editing workflow — **AI edits land as drafts → user reviews the diff → user
accepts → draft becomes the formal version** — to project and document management, plus a
Google Docs import pipeline, all running locally against a plain folder of Markdown files.

## What shipped

**MCP server** (`claude-plug-in/mcp/`) — 16 tools:

- Project management (4): `create_project`, `list_projects`, `delete_project`, `rename_project`
- Document management (6): `create_document`, `read_document`, `list_documents`,
  `delete_document`, `rename_document`, `move_document`
- Draft workflow (5): `propose_edit`, `get_draft`, `get_diff`, `accept_draft`, `reject_draft`
- Google Docs import (1): `import_google_doc`

Plus a single `inkclerk://` resource dispatcher covering four URI forms (`projects`, `project`,
`document`, `draft`), and 4 MCP prompts (`edit_document`, `create_document`, `import_google_doc`,
`accept_draft`) for Claude Desktop App users, who don't get slash commands.

**Claude Code skills** (`claude-plug-in/skills/`) — 4 slash commands, each a 1:1 counterpart to
one of the prompts above: `/inkclerk:import-google-doc`, `/inkclerk:propose-edit`,
`/inkclerk:accept-draft`, `/inkclerk:reject-draft`.

**Google Docs import** — a four-stage pipeline, reachable as a non-blocking two-step MCP call
(the first call opens a browser and returns immediately; the second, once the user confirms
they're done, completes the import):

1. Client-side Google sign-in + Picker in `apps/web`, using Google Identity Services — no
   client secret, no server-side code exchange.
2. A secret-free relay in `apps/web-api` hands the picked document's access token to the local
   MCP process, which has no public endpoint of its own.
3. HTML export via the Drive API, converted to Markdown with a custom `markdownify` converter
   that preserves inline visual styles (color, background, font, underline) instead of
   stripping them.
4. Image download, including inline `data:` URI images that Google's HTML export sometimes uses
   in place of an external URL, written into a sibling `-assets/` folder with percent-encoded
   Markdown references.

**Web presence** — `apps/web` ships a homepage, privacy policy, and terms page (used to move the
Google OAuth consent screen to Google's production-verification-submitted state); `apps/web-api`
ships the `/import/google-doc` relay described above. Both are deployed on Render.

**Distribution** — the plugin has been submitted to the Anthropic community marketplace.

## Install

- **Marketplace** (once approved — see Known gaps below):
  ```
  /plugin marketplace add anthropics/claude-plugins-community
  /plugin install inkclerk@claude-community
  ```
- **Dev install** (works today):
  ```
  claude --plugin-dir ./claude-plug-in
  ```

See [`claude-plug-in/README.md`](../../claude-plug-in/README.md) for prerequisites and full tool
reference.

## Known gaps / manual follow-ups

These are tracked, non-blocking items carried over from earlier tasks — see
`docs/execution/v0.1.0.md` for the tasks that introduced them:

- **Real-Google-Doc smoke test** not yet run — unit tests mock the Drive API; an end-to-end
  import against a live Google Doc is still pending (Task 7.14).
- **Interactive verification** not yet run — confirming `/mcp` connection status and that the
  four skills appear in the slash-command picker requires an interactive Claude Code session
  (Task 10.6).
- **OAuth consent screen verification** submitted to Google but not yet approved; until then,
  installers outside the 100-user testing cap may see an "unverified app" warning (Task 11.9).
- **Marketplace listing** submitted for review (Task 12.5); post-approval verification that
  `inkclerk` appears in the public marketplace and installs cleanly end-to-end is pending
  Anthropic's review cycle and the marketplace's nightly sync (Task 12.6).
