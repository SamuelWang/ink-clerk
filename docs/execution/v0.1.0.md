### Runtime Topology

The Claude Plug-in is a locally-running Python MCP server (`claude-plug-in/mcp/`) paired with a set of Claude Code skill definitions (`claude-plug-in/skills/`):

`import_google_doc` additionally depends on two hosted services for the Google sign-in handshake, since the MCP process above has no public endpoint the browser can reach:

```
┌───────────────────────────┐          ┌──────────────────────┐         ┌───────────────────────────┐
│ claude-plug-in/mcp (local) │          │ apps/web (Render,     │         │ apps/web-api (Render,     │
│                            │          │ public, static)       │         │ public)                   │
│ tools/import_google_doc.py │          │                        │         │                           │
│  - opens system browser to │  HTTP    │ /import/google-doc     │  HTTPS  │ routers/import_session.py │
│    {WEB_APP_URL}/…         ┼─────────►│  - Google Identity     ┼────────►│  POST /import/google-doc/ │
│  - polls session endpoint  │          │    Services token      │         │        session/{id}/      │
│    at {WEB_API_URL}/…      │◄─────────┼    client (client-side,│         │        complete           │
└─────────────────────────────┘  HTTPS  │    no client secret)   │         │  GET  /import/google-doc/ │
                                          │  - Google Picker        │         │        session/{id}       │
                                          │    (client-side)        │         │  (never talks to Google,  │
                                          └───────────┬────────────┘         │   no client secret)       │
                                                       │ HTTPS                └───────────────────────────┘
                                                       ▼
                                          accounts.google.com (sign-in + consent)
```

The browser is the only party that ever talks to Google. `apps/web-api` only relays the already-obtained `{access_token, expires_in, file_id, file_name}` from the browser to the local MCP process.

**Transport: stdio.** The MCP server is launched as a subprocess (`uv run python main.py`). The Claude client communicates with it over stdin/stdout using the MCP JSON-RPC protocol. No HTTP server is started.

**SDK style: FastMCP.** The official MCP Python SDK's `FastMCP` class is used throughout. Tools, resources, and prompts are registered via Python decorators (`@mcp.tool()`, `@mcp.resource()`, `@mcp.prompt()`). Modules are imported in `main.py` for their side effects (decorator registration).

> **Deviation from `docs/requirements/v0.1.0.md` §2.1:** the requirements doc's directory listing still shows `mcp/src/main.py` etc. under an `mcp/src/` subdirectory. The as-built layout above is flat — `mcp/main.py`, `mcp/tools/`, `mcp/resources/`, etc., with no `src/` layer. See Task 1 below.

**Grouping rationale:**
- `projects.py` and `documents.py` are CRUD tools over distinct entity types; `drafts.py` is the workflow layer; `import_google_doc.py` is a self-contained pipeline. Each file stays under ~200 lines.
- `resources.py` is one file because all four URI handlers share the same dispatch and utility calls.
- `shared/` has no MCP SDK imports — it is a pure utility layer usable by tools, resources, and prompts alike.
- `apps/web-api` is a separate deployable process from `claude-plug-in/mcp` — it runs on a public host (Render), not the user's machine, so the local MCP process (which has no public endpoint) can reach it. It never loads a Google client secret and never talks to Google at all; it's a secret-free relay for the browser → local-process handoff. Only `routers/import_session.py` exists in v0.1.0; `routers/projects.py`, `files.py`, `drafts.py`, `ai.py` are added in Milestone 3.

### `main.py` Entry Point

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("inkclerk")

# Import tool modules for side effects (decorator registration)
import tools.projects          # noqa: F401
import tools.documents         # noqa: F401
import tools.drafts            # noqa: F401
import tools.import_google_doc # noqa: F401
import resources.resources     # noqa: F401
import prompts.prompts         # noqa: F401

if __name__ == "__main__":
    mcp.run()
```

Each tool module imports `mcp` from `main` (or from a shared module-level instance) and registers its tools at import time via `@mcp.tool()`. `mcp.run()` blocks on stdin, serving JSON-RPC requests.

### Tool Implementation Pattern

Every tool in `tools/*.py` follows this skeleton:

```python
@mcp.tool(annotations={"readOnlyHint": True})  # annotation varies per tool
def read_document(project_name: str, doc_path: str) -> dict:
    # Step 1 — resolve project
    project_path, _ = resolve_project(project_name)
    # raises ProjectNotFoundError or AmbiguousProjectNameError

    # Step 2 — resolve document
    abs_path = resolve_doc(project_path, doc_path)
    # raises DocumentNotFoundError

    # Step 3 — perform operation
    text = abs_path.read_text(encoding="utf-8")
    meta, body = parse(text)

    # Step 4 — return result dict
    return {
        "content": body,
        "doc_id": meta.get("id"),
        "last_modified": meta.get("lastModified"),
        "has_draft": draft_path_for(project_path, doc_path).exists(),
    }
```

`list_projects` is the sole exception: it scans `PROJECTS_ROOT` directly without calling `resolve_project`.

**Error interception:** FastMCP wraps each tool call. Any `InkClerkError` raised inside a tool is caught, serialized with `.to_dict()`, and returned as a tool result with the MCP `isError: true` flag set. This keeps all tool functions free of error-formatting boilerplate. Unhandled exceptions are caught by the same wrapper, logged, and returned as `{"error": "INTERNAL_ERROR", "message": "..."}` with `isError: true`.

### Python Version and Tooling

- Python `>=3.11` required. The `match` statement (3.10+) is used in the resource dispatcher (Task 8).
- `uv` is the sole package manager. No `pip`, `requirements.txt`, or `setup.py`.
- `uv run python main.py` auto-creates the virtualenv and installs dependencies on first run.
- No `__main__.py`; `main.py` is invoked directly as `python main.py` from the `mcp/` directory. All intra-package imports use the `shared.*`, `tools.*`, etc. style.

### 2a. `errors.py`

**Design:**

```python
class InkClerkError(Exception):
    code: str = "INTERNAL_ERROR"

    def to_dict(self) -> dict:
        return {"error": self.code, "message": str(self)}


class ProjectNotFoundError(InkClerkError):
    code = "PROJECT_NOT_FOUND"

class AmbiguousProjectNameError(InkClerkError):
    code = "AMBIGUOUS_PROJECT_NAME"

class DocumentNotFoundError(InkClerkError):
    code = "FILE_NOT_FOUND"

class FileAlreadyExistsError(InkClerkError):
    code = "FILE_ALREADY_EXISTS"

class FolderAlreadyExistsError(InkClerkError):
    code = "FOLDER_ALREADY_EXISTS"

class NoDraftError(InkClerkError):
    code = "NO_DRAFT"

class AuthRequiredError(InkClerkError):
    code = "AUTH_REQUIRED"

class GoogleApiError(InkClerkError):
    code = "GOOGLE_API_ERROR"

class PermissionDeniedError(InkClerkError):
    code = "PERMISSION_DENIED"
```

Any Python exception that is not an `InkClerkError` (e.g. `PermissionError` from the OS, `json.JSONDecodeError`) is caught at the MCP layer, wrapped in a base `InkClerkError`, and returned as `INTERNAL_ERROR`. All tool errors return the structured payload `{"error": "<CODE>", "message": "..."}`, propagating as: tool function raises an `InkClerkError` subclass → the FastMCP tool wrapper catches it → calls `.to_dict()` → returns it as tool result content with `isError: true` in the MCP response. This is distinct from a protocol-level MCP error (e.g., unknown method), which the SDK handles separately.

### 2b. `frontmatter.py`

**Design:**

- `parse(text: str) -> tuple[dict, str]`: if `text` starts with `---\n`, reads lines until the next `---\n` (or `---` followed by EOF), parses the YAML block with `yaml.safe_load` (never `yaml.load` — prevents arbitrary code execution from a malformed file), and returns `(meta_dict, body)` where `body` is the text after the closing delimiter with a single leading newline stripped. No frontmatter block present → returns `({}, text)`. Malformed YAML → returns `({}, text)` and emits a warning rather than raising.
- `write(meta: dict, body: str) -> str`: serializes `meta` with `yaml.dump(default_flow_style=False, allow_unicode=True)` and returns `---\n{yaml block}---\n\n{body}`. `allow_unicode=True` ensures CJK characters in frontmatter values are written as raw Unicode, not escaped sequences.
- **Draft frontmatter rule:** draft files carry no frontmatter — a draft is pure Markdown body content. When `accept_draft` runs, it reads the formal file's existing frontmatter (`id`, `created`), combines it with the draft body, updates `lastModified` to the current UTC timestamp, and writes the merged result back to the formal file path.

**Sub-tasks:**

- [x] 2b.1. Write tests for `parse`:

  - Input with frontmatter followed by empty body — verify body is empty string (not `None`).

- [x] 2b.2. Write tests for `write`:

### 2c. `fs.py`

**Design:**

`PROJECTS_ROOT: Path = Path.home() / "Documents" / "InkClerk"` is hard-coded as a module-level constant for v0.1.0. Future milestones may read it from a user config file; the constant name makes it easy to locate.

- `slugify(name: str) -> str`: lowercase the string; replace every run of whitespace and non-alphanumeric characters with a single hyphen; strip leading/trailing hyphens. Non-ASCII letters (e.g. `é`, `中`) are treated as alphanumeric and preserved in project slugs (e.g. `"Meeting Notes!"` → `"meeting-notes"`). Note: Google Doc import slugs use a stricter rule (non-ASCII stripped) and don't reuse this function — `import_google_doc.py` derives its own slug.
- `resolve_project(name: str) -> tuple[Path, dict]`: scans the immediate children of `PROJECTS_ROOT` (no recursive descent), checks each for `.inkclerk/project.json`, and compares its `name` field to the argument case-insensitively. Returns `(project_path, project_json_dict)` on a unique match; raises `AmbiguousProjectNameError` on multiple matches, `ProjectNotFoundError` on none. No result caching — `PROJECTS_ROOT` is scanned on every call (expected fast for <100 projects).
- `resolve_doc(project_path: Path, doc_path: str) -> Path`: resolves `project_path / doc_path` to an absolute path, verifies it's still under `project_path` (prevents directory traversal via `..`), and raises `DocumentNotFoundError` if the path doesn't exist or isn't a file.
- `draft_path_for(project_path: Path, rel_path: str) -> Path`: returns `project_path / ".inkclerk" / "drafts" / rel_path`. Does not check existence; callers check themselves.
- `ensure_dir(path: Path) -> None`: thin wrapper around `path.mkdir(parents=True, exist_ok=True)`.

## Google Docs Import Pipeline — Current Design (post Task 7d)

`import_google_doc` executes four sequential stages, carried over from the retired system-design doc and kept current as of Task 7d.

### 7.1 Stage 1 — Client-Side Google Sign-In and Document Pick

Neither Google's sign-in flow nor a public HTTPS redirect target is available to
`claude-plug-in/mcp` — it's a local stdio subprocess with no reachable endpoint, and Google's
client-side token model needs a browser anyway. Instead, the MCP process opens the system browser
to the hosted `apps/web` app's `/import/google-doc` page, which obtains a `drive.file`
access token **directly from Google** using Google Identity Services
(`google.accounts.oauth2.initTokenClient`) — no client secret, no code exchange, entirely
client-side — and drives the Google Picker so the user picks the target document. Once both steps
complete, that page POSTs the result to the hosted `apps/web-api` relay, which the MCP
process polls. `apps/web-api` never talks to Google and never holds a client secret; it only
relays `{access_token, expires_in, file_id, file_name}` from the browser to the local process.

Config: `INKCLERK_WEB_APP_URL` (opens the browser here) and `INKCLERK_WEB_API_URL` (polled for the
result) env vars on the MCP server, pointing at the deployed `apps/web` and `apps/web-api` Render
URLs respectively. Set via `claude-plug-in/.mcp.json`'s `env` block when launched through the
Claude Code plugin; must be set manually when running the MCP server any other way.

There is no local client-credentials file — `~/.config/inkclerk/google-oauth-client.json` is not
part of the design, and no access token is cached to disk either: `drive.file` only grants access
to the specific document picked through the Picker, and picking a document is how the caller
learns *which* document to import in the first place, so every call needs its own fresh
browser + Picker round regardless of whether a still-valid token exists. The Google OAuth client
ID and Picker API key are both meant to be public (embedded in the `apps/web` browser bundle); no
Google client secret exists anywhere in this system.

OAuth scope (requested client-side by the `apps/web` Picker page):
`https://www.googleapis.com/auth/drive.file`. Unlike `drive.readonly` (a *restricted* scope,
requiring Google's CASA security assessment and a demo video to verify), `drive.file` is a
*sensitive* scope: it only grants access to files the user explicitly selects through a Google
Picker (or files the app creates), never blanket read access to the user's whole Drive.

**No refresh token is ever issued** — this is inherent to Google Identity Services' client-side
token model (`initTokenClient`), not a limitation of this design. Since no token is cached, this
has no practical consequence: every call already runs the full flow below rather than refreshing
anything.

**Flow** (two steps, since Task 7d — see the goal note under that task for why this replaced a
single blocking call):

*Step 1 — no `session_id` supplied:*

1. If `INKCLERK_WEB_APP_URL` or `INKCLERK_WEB_API_URL` is unset, raise `AuthRequiredError`
   immediately.
2. Generate `session_id = uuid4()`.
3. Build `sign_in_url = {WEB_APP_URL}/import/google-doc?session_id={session_id}` and best-effort
   open the system browser to it (`webbrowser.open`) — the page there requests a token from
   Google (client-side) and drives the Picker; see §7.5.
4. Return `{"status": "pending", "session_id": session_id, "sign_in_url": sign_in_url}`
   immediately. No polling happens on this call; the caller is expected to relay `sign_in_url` to
   the user, wait for them to confirm they've finished, and only then make step 2's call.

*Step 2 — `session_id` supplied:*

1. Poll `GET {WEB_API_URL}/import/google-doc/session/{session_id}` up to 5 times, 2 seconds apart
   (`CHECK_ATTEMPTS = 5`, `CHECK_INTERVAL_SECONDS = 2` — a short check, ~10s total, not a
   long-running wait):
   - `{"status": "ready", "access_token": ..., "expires_in": ..., "file_id": ..., "file_name": ..., "resource_key": ...}` → build a `google.oauth2.credentials.Credentials(token=access_token)` and proceed to Stage 2 using `file_id` (and `resource_key`, if non-empty — see below). The relay deletes the session entry once retrieved (single-claim).
   - `{"status": "expired"}` → raise `AuthRequiredError` (the caller must restart from step 1 for
     a fresh `session_id`/link).
   - `{"status": "pending"}`, a request error, or exhausting all 5 attempts → raise
     `AuthRequiredError` telling the caller the sign-in/Picker step doesn't look complete yet; the
     caller should ask the user to confirm again and retry step 2 with the *same* `session_id`.

For documents in a shared drive, the Picker also supplies a `resourceKey`, relayed through the
session as `resource_key` (§7.5, §5.1/§5.2 of the requirements doc). When non-empty, it's set as
`X-Goog-Drive-Resource-Keys: {file_id}/{resource_key}` on the Drive API calls in Stage 2.

Because the token just granted is always scoped to the file just picked, a 403 from the Drive API
in Stage 2 is treated as a real permission error (`PermissionDeniedError`), not something to retry
— there is no stale-token scenario to recover from.

### 7.2 Stage 2 — HTML Export via Drive API

```python
service = googleapiclient.discovery.build("drive", "v3", credentials=creds)
html_bytes = service.files().export(fileId=doc_id, mimeType="text/html").execute()
html = html_bytes.decode("utf-8")
```

Error handling:
- `HttpError` with status 403 → raise `PermissionDeniedError`.
- Any other `HttpError` → raise `GoogleApiError(f"Drive API error {status}: {reason}")`.

The Drive API HTML export is preferred over the Docs API JSON representation because it produces self-contained HTML suitable for direct conversion by `markdownify`.

### 7.3 Stage 3 — HTML → Markdown Conversion

**BeautifulSoup pre-processing pass** (before `markdownify`):

Parse the HTML with `BeautifulSoup(html, "html.parser")`. Collect all `<img src="...">` URLs during this pass for Stage 4. Do **not** strip or modify any `style` attributes — visual styles are preserved by the custom converter below.

**markdownify conversion:**

Use a custom `MarkdownConverter` subclass with two additional converters:

- `convert_span(el, text, convert_as_inline)`: If the `<span>` element's `style` attribute contains any of `color`, `background-color`, `font-family`, `font-size`, or `text-decoration`, emit `<span style="…">text</span>` verbatim (preserving only those properties; stripping any that are not in this set). Otherwise return `text` unchanged.
- `convert_u(el, text, convert_as_inline)`: Emit `<u>text</u>` verbatim, preserving underline applied via `<u>` elements.

```python
import markdownify

class InkClerkConverter(markdownify.MarkdownConverter):
    VISUAL_PROPS = {"color", "background-color", "font-family", "font-size", "text-decoration"}

    def convert_span(self, el, text, convert_as_inline):
        style = el.get("style", "")
        kept = [
            p.strip() for p in style.split(";")
            if p.strip() and p.strip().split(":")[0].strip() in self.VISUAL_PROPS
        ]
        if kept:
            return f'<span style="{"; ".join(kept)};">{text}</span>'
        return text

    def convert_u(self, el, text, convert_as_inline):
        return f"<u>{text}</u>"

md = InkClerkConverter(heading_style="atx", bullets="-").convert(html)
```

`heading_style="atx"` produces `#`-prefix headings (`# H1`, `## H2`, …) for all six levels. The alternative Setext style (`===` underlines) only supports two levels and is not used. `markdownify` defaults to Setext for H1/H2, so this argument is required.

`dropped_styles` always returns `[]`; no style tracking is needed.

**Unified diff note (`get_diff` tool):** `get_diff` uses Python's stdlib `difflib.unified_diff`, not `diff-match-patch`. `difflib.unified_diff` takes two lists of lines and directly produces the standard `+`/`-`/`@@` unified diff format suitable for display in a fenced `diff` code block. `diff-match-patch` is a character-level differ designed for operational transformation (it is what `packages/editor` uses for TipTap `DraftAddition`/`DraftDeletion` marks). It does not produce unified diff format natively and is the wrong tool for `get_diff`. `diff-match-patch` remains in `pyproject.toml` for the future editor integration.

### 7.4 Stage 4 — Image Download and Document Creation

**Image download:**

For each `<img>` `src` collected in Stage 3, one of two paths:

- **`data:` URI** (Google's HTML export embeds some images this way instead of an external URL):
  decode it in place via `_decode_data_url` — split the header/payload, extract the MIME type, and
  either `base64.b64decode` the payload (when the header includes `;base64`) or URL-decode it as
  UTF-8 text otherwise. No HTTP request is made. The extension is guessed from the MIME type via
  `mimetypes.guess_extension` (falling back to `.bin` if unrecognized), and the file is named
  `image-{i}{ext}` (`i` = the image's position among the doc's images).
- **External URL:** issue an authenticated GET request using
  `google.auth.transport.requests.AuthorizedSession(creds)`, and derive the output filename from
  the URL's path component.

Then, for either path:
1. Apply the 255-byte truncation rule (see `docs/architecture.md`'s Unicode/CJK filenames section).
2. Write raw bytes to `{project_path}/{subdirectory}/{output_slug}-assets/{image_filename}`.
3. Replace the `src` attribute in the converted Markdown with the `./`-prefixed, percent-encoded relative path.

**Output filename:**

If the `filename` argument is provided, use it directly. Otherwise, fetch the Google Doc title:

```python
meta = service.files().get(fileId=doc_id, fields="name").execute()
title = meta["name"]
```

Slugify the title for the output filename: lowercase, spaces → hyphens, non-ASCII characters stripped (unlike project slugs, which preserve non-ASCII).

**Document creation:**

Prepend InkClerk frontmatter to the converted Markdown body:

```markdown
---
id: <new uuid7>
created: <utc-iso8601 now>
lastModified: <utc-iso8601 now>
---

{converted markdown body}
```

Write to `{project_path}/{subdirectory}/{output_filename}.md`. If the file already exists, raise `FileAlreadyExistsError`.

Return `doc_path` and `doc_id`. `dropped_styles` is always `[]`.

### 7.5 Client-Side Picker (`apps/web`) and Import Relay (`apps/web-api`)

Two small hosted pieces replace the OAuth broker: an interactive page in `apps/web` that talks to
Google directly, and a secret-free relay in `apps/web-api` that hands the result to the local MCP
process. Neither ever loads a Google client secret.

**`apps/web`'s `/import/google-doc` page:** a client-side-only React route (not part of the
prerendered marketing pages). Reads `session_id` from the query string. On a "Sign in with Google"
button click (a user gesture is required to pop Google's consent window), calls
`google.accounts.oauth2.initTokenClient({client_id, scope: 'drive.file', callback}).requestAccessToken()`
— entirely client-side, via the Google Identity Services library
(`https://accounts.google.com/gsi/client`). Once the access token comes back, it loads the Picker
JS library (`https://apis.google.com/js/api.js`) and opens a `google.picker.PickerBuilder`
scoped to a Google Docs view (`setOAuthToken`, `setDeveloperKey`) — this is the step that actually
grants `drive.file` access to the specific document the user picks. Once a document is picked, the
page reads `resourceKey` off the Picker response (present for documents in a shared drive, `""`
otherwise) and `POST`s `{access_token, expires_in, file_id, file_name, resource_key}` to the
`apps/web-api` relay below, then tells the user they can return to their terminal.

**`apps/web-api`'s `routers/import_session.py`:** an in-memory session store (`session_id ->
{status, access_token, expires_in, file_id, file_name, resource_key, created_at}`) is sufficient for v0.1.0 —
no database is introduced (Postgres arrives with the rest of `apps/web-api` in Milestone 3).
`status` moves straight to `"ready"` on `POST .../complete` (both sign-in and picking already
happened client-side by then), then to `"expired"` on first claim by `GET .../session/{id}`, or if
the TTL (10 minutes) elapses unclaimed. Because Render's free tier can recycle the process, an
in-progress import that outlives a restart simply requires the user to retry — acceptable for
v0.1.0.

**Endpoints:**

| Endpoint | Method | Behavior |
|---|---|---|
| `/import/google-doc/session/{session_id}/complete` | POST | Body `{"access_token": "...", "expires_in": ..., "file_id": "...", "file_name": "...", "resource_key": ""}`, called by the `apps/web` Picker page's own JS once the user signs in and picks a document. `resource_key` defaults to `""` and is only non-empty for documents in a shared drive. Stores the payload under `session_id`, status `"ready"`. |
| `/import/google-doc/session/{session_id}` | GET | Returns `{"status": "pending"}` if not yet completed, `{"status": "expired"}` if the TTL elapsed or it was already claimed, or the stored token + picked-file payload (including `resource_key`) (and deletes the entry) if ready. |

**Config (env vars):**

| Variable | Purpose |
|---|---|
| `WEB_APP_ORIGIN` | The deployed `apps/web` origin, used to restrict CORS on `POST .../complete` (that request is cross-origin, from `apps/web`'s origin to this service) |

`apps/web` needs its own env vars (build-time, `VITE_`-prefixed, all meant to be public since
they're embedded in the browser bundle): `VITE_GOOGLE_CLIENT_ID`, `VITE_GOOGLE_APP_ID`,
`VITE_GOOGLE_PICKER_API_KEY`, `VITE_WEB_API_URL` (this service's own deployed URL).

**Google Cloud setup (one-time, maintainer-only):**

1. Create a Google Cloud project → enable the Google Drive API and the Google Picker API.
2. Note the project's **project number** (Cloud Console → the project picker / dashboard's "Project info" card — a purely numeric value, distinct from the project ID string used elsewhere in the URL/CLI). The Picker must be initialized with this value via `.setAppId(...)`; without it, an OAuth token scoped to `drive.file` is never actually granted access to the file the user picks, and the Drive API's `files.get`/`files.export` calls 404 afterward (Google returns 404 rather than 403 here to avoid revealing whether the file exists to a caller without access) — see https://stackoverflow.com/questions/51488303/google-drive-rest-api-get-file-returns-404-with-scope-drive-file-only.
3. Configure the OAuth consent screen (External). **Testing mode is sufficient to develop and exercise Task 6/7, but moving to Production for public marketplace distribution (Task 12) requires Google's verification** — a public Application home page and Application privacy policy link, plus an app logo. `drive.file` is a *sensitive* scope (unlike the *restricted* `drive.readonly` it replaces), so this verification does not require a CASA security assessment or a demo video. See Task 11, which stands up `apps/web`'s homepage/privacy/terms pages specifically to satisfy this and submits the consent screen for verification.
4. Create an OAuth client of type **Web application** under Credentials. Client secrets aren't used for this flow — only the client ID is needed, and it's meant to be public.
5. Add `apps/web`'s deployed origin (and a `localhost` dev origin) as authorized JavaScript origins. No redirect URI is needed — the Identity Services token client never redirects back through Google.
6. Create a separate API key for the Picker API, restricted by HTTP referrer to `apps/web`'s origin.
7. Store the resulting client ID, project number, and Picker API key as `apps/web`'s Render environment variables (`VITE_GOOGLE_CLIENT_ID`, `VITE_GOOGLE_APP_ID`, `VITE_GOOGLE_PICKER_API_KEY`) — never in the repo. No secret exists to protect.

**Deployment (Render):**

  `uvicorn main:app --app-dir src --host 0.0.0.0 --port $PORT`).
