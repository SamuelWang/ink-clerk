## Task 7 — Google Docs Import Tool

**Goal:** Implement the `import_google_doc` tool as a 5-stage pipeline.

### Stage 2 — OAuth via Hosted Broker and Token Cache

**Sub-tasks:**

- [x] 7.3. Write tests for the OAuth helper (mock `httpx` calls to `INKCLERK_AUTH_SERVICE_URL`, and the local token-cache file):
  - No cached token file → opens the browser to `{AUTH_SERVICE_URL}/auth/google/start` and polls `{AUTH_SERVICE_URL}/auth/google/session/{id}` until `status: "ready"`, then writes `{access_token, refresh_token, expiry}` to the cache file.
  - Poll timeout / `status: "expired"` → raises `AuthRequiredError`.
  - Valid cached token with unexpired `access_token` → builds `Credentials` directly, no network call.
  - Expired cached `access_token` → calls `POST {AUTH_SERVICE_URL}/auth/refresh` with the cached `refresh_token`, and rewrites the cache file with the new `access_token`/`expiry`.
  - Auth service unreachable at any step → raises `AuthRequiredError`.

  - Token cache path: `~/.config/inkclerk/google-token.json` (now storing `{access_token, refresh_token, expiry}`, not `creds.to_json()`).
  - First-run: browser + session poll against `INKCLERK_AUTH_SERVICE_URL` (Task 6's service).
  - Subsequent runs: load cache; refresh via the hosted `/auth/refresh` endpoint when expired.
  - Remove the now-unused `google-auth-oauthlib` dependency from `claude-plug-in/mcp/pyproject.toml` (added back in Task 1.2, before this OAuth redesign) and add `google-auth` instead, per system design §3.2.

Known residual limitation: the SDK's template match regex is `[^/]+` per `{}` param, so a *live* MCP protocol resource read (not our unit tests, which call `dispatch()` directly) for a `document`/`draft` URI whose `path` query value contains `/` (a document in a subdirectory) will fail to route. Flagged as a follow-up; out of scope to fix without bypassing FastMCP's decorator for a hand-rolled low-level `Server` resource handler.
  - Handler bodies reuse the existing tools layer directly (`tools.projects.list_projects`, `tools.documents.list_documents`/`read_document`, `tools.drafts.get_draft`) rather than re-deriving logic against `shared/`, since their output schemas already match the resource schemas exactly.

- [x] 8.6. Wire module into `main.py`.
  - Cross-module imports in `resources/resources.py` use `import tools.projects` (not `from tools.projects import list_projects`) — the `from X import Y` form triggered a real `ImportError: cannot import name 'list_projects' from partially initialized module` due to this codebase's existing `main.py`/`tools/*.py` circular-import structure (`tools/*.py` do `from main import mcp`, which — when `main.py` is run as a script — re-imports `main.py` as a second module under the fresh name `"main"`, racing the first, still-partial `tools.projects` import). The bare `import tools.projects` form (lazy attribute access at call time, same pattern already used for `shared.fs`) avoids the race. Verified `uv run python main.py` starts cleanly.
