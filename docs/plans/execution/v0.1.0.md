# Execution Plan — v0.1.0 Claude Plug-in

## Overview

This document breaks down the v0.1.0 Claude Plug-in milestone into ordered implementation tasks. Each task includes sub-tasks written in TDD order: tests first, then implementation, then wiring/verification.

**References:**
- Requirements: `docs/plans/requirements/v0.1.0.md`
- System Design: `docs/plans/system-design/v0.1.0.md`

**Dependency order:** Shared utilities → Project tools → Document tools → Draft tools → Google Docs import → Resource handlers → Prompt handlers → Skills

---

## Task 1 — Sub-project Initialization

**Goal:** Scaffold the `claude-plug-in/` directory structure and establish the Python project.

**Files to create:**
```
claude-plug-in/
├── .claude-plugin/
│   └── plugin.json      (plugin manifest)
├── .mcp.json            (MCP server wiring)
├── mcp/
│   ├── pyproject.toml
│   └── src/
│       ├── main.py
│       ├── tools/__init__.py
│       ├── resources/__init__.py
│       ├── prompts/__init__.py
│       └── shared/__init__.py
└── skills/              (empty — populated in Task 9)
```

**Sub-tasks:**

1.1. Initialize the MCP server Python project:
  ```bash
  mkdir -p claude-plug-in/mcp
  cd claude-plug-in/mcp && uv init --name inkclerk-mcp
  ```
  `uv init` generates `pyproject.toml`, `.python-version`, `README.md`, `hello.py` (hello-world stub), and `.gitignore`. Delete the generated `hello.py` — the real entry point is created in sub-task 1.3.

1.2. Add all required dependencies:
  ```bash
  cd claude-plug-in/mcp && uv add mcp uuid7 google-api-python-client \
    google-auth-oauthlib markdownify diff-match-patch pyyaml beautifulsoup4
  ```
  `uv add` pins deps into `pyproject.toml`, creates `.venv/`, and generates `uv.lock`. Then manually set `requires-python = ">=3.11"` and `version = "0.1.0"` in `pyproject.toml` (uv init may pin to the exact interpreter version).

1.3. Create `claude-plug-in/mcp/src/main.py` with the `FastMCP("inkclerk")` instance and side-effect imports for all tool/resource/prompt modules (imports commented out until modules exist).

1.4. Create `__init__.py` stubs for `tools/`, `resources/`, `prompts/`, and `shared/`.

1.5. Verify the server starts without error:
  ```
  cd claude-plug-in/mcp && uv run python src/main.py
  ```

1.6. Create `claude-plug-in/.claude-plugin/plugin.json`:
  ```json
  {
    "name": "inkclerk",
    "description": "MCP server and slash commands for AI-first document editing with the InkClerk draft/accept workflow",
    "version": "0.1.0",
    "author": {
      "name": "Samuel Wang",
      "email": "chieh0919@gmail.com"
    }
  }
  ```

1.7. Create `claude-plug-in/.mcp.json` to wire the MCP server into the plugin:
  ```json
  {
    "inkclerk": {
      "command": "uv",
      "args": ["run", "python", "src/main.py"],
      "cwd": "${CLAUDE_PLUGIN_ROOT}/mcp"
    }
  }
  ```
  `${CLAUDE_PLUGIN_ROOT}` is resolved by Claude Code to the plugin directory — keeps the path portable across installs.

1.8. Verify the plugin loads:
  ```bash
  # Load for this session only (development):
  claude --plugin-dir ./claude-plug-in

  # Permanent local install (symlink into skills directory):
  ln -s ~/projects/ink-clerk/claude-plug-in ~/.claude/skills/inkclerk
  ```
  Confirm the `inkclerk` MCP server is connected (`/mcp` status in Claude Code).

### 2a. `errors.py`

**Sub-tasks:**

2a.2. Write tests for each error subclass — verify the `code` attribute matches the expected string for: `ProjectNotFoundError`, `AmbiguousProjectNameError`, `DocumentNotFoundError`, `FileAlreadyExistsError`, `FolderAlreadyExistsError`, `NoDraftError`, `AuthRequiredError`, `GoogleApiError`, `PermissionDeniedError`.

2a.3. Implement `errors.py` with `InkClerkError` base class and all nine subclasses as specified in system design §4.3.

2a.4. Run tests; all pass.

### 2b. `frontmatter.py`

**Sub-tasks:**

2b.1. Write tests for `parse`:
  - Input with valid YAML frontmatter block — verify `(meta, body)` split.
  - Input with no frontmatter — verify returns `({}, text)`.
  - Input with malformed YAML — verify returns `({}, text)` without raising.
  - Input with frontmatter followed by empty body — verify body is empty string (not `None`).

2b.2. Write tests for `write`:
  - Round-trip: `write(*parse(text)) == text` for well-formed input.
  - CJK values in `meta` are written as raw Unicode (not `\uXXXX` escape sequences).

2b.3. Write tests for the draft frontmatter rule — confirm that a draft body passed through `parse` returns `{}` for meta (draft files carry no frontmatter).

2b.4. Implement `parse` and `write` in `frontmatter.py` using `yaml.safe_load` / `yaml.dump(allow_unicode=True)` as specified in system design §4.2.

2b.5. Run tests; all pass.

### 2c. `fs.py`

**Sub-tasks:**

2c.1. Write tests for `slugify`:
  - `"Meeting Notes"` → `"meeting-notes"`
  - `"Meeting Notes!"` → `"meeting-notes"`
  - `"  --hello--  "` → `"hello"`
  - Non-ASCII letters preserved: `"café Notes"` → `"café-notes"`
  - Already slugified input is idempotent.

2c.2. Write tests for `resolve_project` using a temporary directory as `PROJECTS_ROOT`:
  - Single matching project → returns `(path, json_dict)`.
  - No match → raises `ProjectNotFoundError`.
  - Two projects with the same name (case-insensitive) → raises `AmbiguousProjectNameError`.
  - Case-insensitive match: project named `"Meeting Notes"` is found by `"meeting notes"`.

2c.3. Write tests for `resolve_doc`:
  - Valid relative path within project → returns resolved `Path`.
  - Path traversal (`../outside`) → raises `DocumentNotFoundError`.
  - Non-existent file → raises `DocumentNotFoundError`.

2c.4. Write tests for `draft_path_for` — verify the returned path equals `project_path / ".inkclerk" / "drafts" / rel_path`.

2c.5. Write tests for `ensure_dir` — verify it creates nested directories idempotently.

2c.6. Implement `fs.py` with `PROJECTS_ROOT`, `slugify`, `resolve_project`, `resolve_doc`, `draft_path_for`, and `ensure_dir` as specified in system design §4.1.

2c.7. Run tests; all pass.

## Task 4 — Document Tools

**Goal:** Implement the six document-level MCP tools.

**File:** `claude-plug-in/mcp/src/tools/documents.py`

**Sub-tasks:**

4.1. Write tests for `create_document`:
  - Creates `{project}/{subdirectory}/{filename}.md` with UUID v7 frontmatter.
  - Intermediate directories are created if needed.
  - Returns `doc_path` and `doc_id`.
  - Raises `FileAlreadyExistsError` when target file exists.
  - Raises `ProjectNotFoundError` / `AmbiguousProjectNameError` appropriately.

4.2. Write tests for `read_document`:
  - Returns `content` (body without frontmatter), `doc_id`, `last_modified`, `has_draft`.
  - `has_draft` is `true` when a draft file exists at the expected path, `false` otherwise.
  - Raises `FileNotFoundError` when document does not exist.

4.3. Write tests for `list_documents`:
  - Returns an array entry for each `.md` file in the project tree.
  - Each entry contains `doc_path`, `doc_id`, `relative_path`, `last_modified`, `has_draft`.
  - `has_draft` reflects actual draft existence.

4.4. Write tests for `delete_document`:
  - Deletes the formal `.md` file.
  - Also deletes the draft file if one exists (`draft_deleted: true`).
  - Returns `draft_deleted: false` when no draft exists.
  - Raises `FileNotFoundError` when document does not exist.

4.5. Write tests for `rename_document`:
  - Renames `{old_stem}.md` → `{new_filename}.md` in the same directory.
  - Moves draft file from old draft path to new draft path if it exists (`draft_moved: true`).
  - Renames sibling assets folder `{old_stem}-assets/` → `{new_filename}-assets/` if it exists (`assets_moved: true`).
  - When assets folder is renamed, rewrites all `"./{old_stem}-assets/"` occurrences in the document body to `"./{new_filename}-assets/"`.
  - Updates `lastModified` in frontmatter.
  - Raises `FileAlreadyExistsError` when `{new_filename}.md` already exists.

4.6. Write tests for `move_document`:
  - Moves document to a new path within the same project.
  - Moves document to a path in a different project.
  - Handles cross-device moves (uses `shutil.move`).
  - Moves draft to `<dst-project>/.inkclerk/drafts/<destination_path>` if draft exists.
  - Moves assets folder to `{new_stem}-assets/` next to new doc location if it exists.
  - Rewrites assets references in document body when stem changes.
  - Raises `FileAlreadyExistsError` when destination file already exists.
  - Validates destination path is under destination project root (rejects `..` traversal).

4.7. Implement all six document tools in `documents.py` using `@mcp.tool()` decorators and shared utilities.

4.8. Wire module into `main.py`.

4.9. Run tests; all pass.

## Task 5 — Draft Tools

**Goal:** Implement the five draft-workflow MCP tools.

**File:** `claude-plug-in/mcp/src/tools/drafts.py`

**Sub-tasks:**

5.1. Write tests for `propose_edit`:
  - Writes content to `.inkclerk/drafts/<rel>.md`, creating directories lazily.
  - Returns `draft_path` and `overwritten: false` on first write.
  - Returns `overwritten: true` when replacing an existing draft.
  - Raises `FileNotFoundError` when the formal document does not exist.

5.2. Write tests for `get_draft`:
  - Returns `content` (body only, no frontmatter) and `draft_path`.
  - Raises `NoDraftError` when no draft exists.

5.3. Write tests for `get_diff`:
  - Returns a valid unified diff string (`---` / `+++` / `@@` format).
  - `additions` and `deletions` counts are accurate.
  - Empty diff when formal and draft content are identical.
  - Raises `NoDraftError` when no draft exists.

5.4. Write tests for `accept_draft`:
  - Writes draft body to formal file, preserving original `id` and `created`, updating `lastModified` to now.
  - Deletes the draft file after acceptance.
  - Returns the updated `doc_path`.
  - Raises `NoDraftError` when no draft exists.

5.5. Write tests for `reject_draft`:
  - Deletes the draft file without modifying the formal document.
  - Returns `draft_path` of the deleted draft.
  - Raises `NoDraftError` when no draft exists.

5.6. Implement all five draft tools in `drafts.py` using `difflib.unified_diff` for `get_diff` (not `diff-match-patch`) as noted in system design §7.4.

5.7. Wire module into `main.py`.

5.8. Run tests; all pass.

## Task 6 — Google Docs Import Tool

**Goal:** Implement the `import_google_doc` tool as a 5-stage pipeline.

**File:** `claude-plug-in/mcp/src/tools/import_google_doc.py`

### Stage 1 — URL / ID Parsing

**Sub-tasks:**

6.1. Write tests for the URL/ID parser:
  - Edit URL (`https://docs.google.com/document/d/{ID}/edit`) → extracts ID.
  - Bare URL (`https://docs.google.com/document/d/{ID}/`) → extracts ID.
  - Bare ID string (`1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgVE2upms`) → returns as-is.
  - `docs.google.com` URL without matching pattern → raises `GoogleApiError`.

6.2. Implement the URL/ID parsing function using the regex `r"/document/d/([a-zA-Z0-9_-]+)"`.

### Stage 2 — OAuth and Token Cache

**Sub-tasks:**

6.3. Write tests for OAuth helper (mock filesystem and `InstalledAppFlow`):
  - No client credentials file → raises `AuthRequiredError`.
  - Valid cached token → loads credentials without browser flow.
  - Expired token with refresh token → calls `creds.refresh()` and rewrites token file.
  - Token file rewritten after refresh (assert write was called).

6.4. Implement OAuth flow:
  - Client credentials path: `~/.config/inkclerk/google-oauth-client.json`
  - Token cache path: `~/.config/inkclerk/google-token.json`
  - Scopes: `documents.readonly` + `drive.readonly`
  - First-run: `InstalledAppFlow.run_local_server(port=0)`
  - Subsequent runs: load and refresh if expired.

### Stage 3 — HTML Export via Drive API

**Sub-tasks:**

6.5. Write tests (mock Drive API):
  - Successful export → returns HTML string.
  - `HttpError` 403 → raises `PermissionDeniedError`.
  - Other `HttpError` → raises `GoogleApiError` with status and reason.

6.6. Implement Drive API export using `googleapiclient.discovery.build("drive", "v3")`.

### Stage 4 — HTML → Markdown Conversion

**Sub-tasks:**

6.7. Write tests for BeautifulSoup pre-processing pass:
  - Elements with `font-family`, `font-size`, `color`, `background-color`, `text-decoration: underline` styles → those properties are stripped.
  - `dropped_styles` list contains exactly the categories found (deduplicated, sorted).
  - Inline images: `<img src="...">` URLs are collected for Stage 5.
  - Heading elements (`h1`–`h6`): `font-size` on these is **not** added to `dropped_styles`.

6.8. Write tests for `markdownify` conversion:
  - Bold → `**text**`, italic → `*text*`, strikethrough → `~~text~~`.
  - Headings use ATX (`#`–`######`) not Setext style.
  - Tables produce GFM table syntax.
  - Ordered lists → `1. item`, unordered → `- item`.

6.9. Implement pre-processing pass and `markdownify.markdownify(clean_html, heading_style="atx", bullets="-")`.

### Stage 5 — Image Download and Document Creation

**Sub-tasks:**

6.10. Write tests for image download (mock `AuthorizedSession`):
  - Image saved to `{project}/{subdirectory}/{slug}-assets/{filename}`.
  - Markdown reference uses percent-encoded `./`-prefixed path.
  - 255-byte filename truncation applied (test with a filename exceeding 255 bytes of UTF-8).
  - CJK filenames: raw Unicode on disk, percent-encoded in Markdown.

6.11. Write tests for document creation:
  - Output filename defaults to Google Doc title (slugified: non-ASCII stripped).
  - Explicit `filename` argument overrides default.
  - InkClerk frontmatter (`id`, `created`, `lastModified`) prepended.
  - Raises `FileAlreadyExistsError` when target file already exists.
  - Returns `doc_path`, `doc_id`, and sorted deduplicated `dropped_styles`.

6.12. Implement Stages 4–5 including `AuthorizedSession` image download, slug derivation, frontmatter injection, and file write.

6.13. Wire module into `main.py`.

6.14. Run tests; all pass. Manual smoke-test: import a real Google Doc (requires OAuth credentials).

## Task 9 — Claude Code Skills

**Goal:** Write the four `SKILL.md` files that define Claude Code slash commands under the `inkclerk` plugin namespace.

**Files to create:**
```
claude-plug-in/skills/
├── import-google-doc/
│   └── SKILL.md
├── propose-edit/
│   └── SKILL.md
├── accept-draft/
│   └── SKILL.md
└── reject-draft/
    └── SKILL.md
```

**Sub-tasks:**

9.1. Write tests / verification criteria (manual, since skill files are prose):
  - Each `SKILL.md` has valid YAML frontmatter with `description` and `argument-hint`.
  - The directory name matches the intended command name (e.g. `import-google-doc/` → `/inkclerk:import-google-doc`).
  - Instruction body covers every step from requirements §4.1–§4.4.

9.2. Write `import-google-doc/SKILL.md`:
  - Frontmatter: `description: Import a Google Doc into an InkClerk project as a Markdown document`, `argument-hint: "[google-doc-url] [project-name] [filename]"`
  - Flow: parse `$ARGUMENTS` → prompt for missing URL/project → call `import_google_doc` → report dropped styles → report created doc path.

9.3. Write `propose-edit/SKILL.md`:
  - Frontmatter: `description: Propose an AI-generated edit to a document and write it as a draft`, `argument-hint: "[instruction]"`
  - Flow: identify target doc → call `read_document` → ask for instruction → generate revised content → call `propose_edit` (warn if `overwritten: true`) → call `get_diff` and display in fenced `diff` block → prompt to run `/inkclerk:accept-draft` or `/inkclerk:reject-draft`.

9.4. Write `accept-draft/SKILL.md`:
  - Frontmatter: `description: Accept the pending draft, making it the formal version of the document`, `argument-hint: "[doc-path]"`
  - Flow: identify target doc → call `get_diff` and display → ask "Accept this draft? (yes/no)" → if yes: call `accept_draft`, report "Draft accepted. The formal document has been updated." → if no: report "Cancelled. The draft was not accepted."

9.5. Write `reject-draft/SKILL.md`:
  - Frontmatter: `description: Discard the pending draft without modifying the formal document`, `argument-hint: "[doc-path]"`
  - Flow: identify target doc → call `get_draft` and show content → ask "Discard this draft? (yes/no)" → if yes: call `reject_draft`, report "Draft discarded. The formal document was not changed." → if no: report "Cancelled. The draft was not discarded."

9.6. Verify integration (plugin must be loaded via `claude --plugin-dir ./claude-plug-in` or installed per Task 1.7):
  - Confirm `inkclerk` MCP server is connected (`/mcp` status in Claude Code).
  - Confirm `/inkclerk:import-google-doc`, `/inkclerk:propose-edit`, `/inkclerk:accept-draft`, and `/inkclerk:reject-draft` appear in the slash-command picker.
