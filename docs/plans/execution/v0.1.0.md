### Stage 2 — OAuth via Hosted Broker and Token Cache

**Superseded by Task 6b:** the broker-based flow described in 7.3/7.4/7.4b below (hosted code exchange, refresh tokens, `INKCLERK_AUTH_SERVICE_URL`) was replaced by a fully client-side Google sign-in + Picker flow in `apps/web`, with `apps/web-api` reduced to a secret-free relay. See Task 6b and system design §7.2 for the current behavior. Left as-is below for history.

**Sub-tasks:**

- [x] 7.3. Write tests for the OAuth helper (mock `httpx` calls to `INKCLERK_AUTH_SERVICE_URL`, and the local token-cache file):
  - No cached token file → opens the browser to `{AUTH_SERVICE_URL}/auth/google/start` and polls `{AUTH_SERVICE_URL}/auth/google/session/{id}` until `status: "ready"`, then writes `{access_token, refresh_token, expiry}` to the cache file.
  - Poll timeout / `status: "expired"` → raises `AuthRequiredError`.
  - Valid cached token with unexpired `access_token` → builds `Credentials` directly, no network call.
  - Expired cached `access_token` → calls `POST {AUTH_SERVICE_URL}/auth/refresh` with the cached `refresh_token`, and rewrites the cache file with the new `access_token`/`expiry`.
  - Auth service unreachable at any step → raises `AuthRequiredError`.

- [x] 7.4. Implement the OAuth helper per system design §7.2:
  - Token cache path: `~/.config/inkclerk/google-token.json` (now storing `{access_token, refresh_token, expiry}`, not `creds.to_json()`).
  - First-run: browser + session poll against `INKCLERK_AUTH_SERVICE_URL` (Task 6's service).
  - Subsequent runs: load cache; refresh via the hosted `/auth/refresh` endpoint when expired.
  - Remove the now-unused `google-auth-oauthlib` dependency from `claude-plug-in/mcp/pyproject.toml` (added back in Task 1.2, before this OAuth redesign) and add `google-auth` instead, per system design §3.2.

- [x] 7.4b. Write tests for and implement the `drive.file` re-auth path: `get_credentials()` gains a `force_reauth` flag and returns `(Credentials, picked)`, where `picked` is the `{"file_id", "file_name"}` the user chose in the Picker when a fresh browser round ran (`None` when reusing a cached/refreshed token). `import_google_doc` catches `PermissionDeniedError` from the title lookup or the HTML export, forces a fresh OAuth+Picker round via `get_credentials(force_reauth=True)`, and retries the failing call once using whatever document was picked; a second consecutive `PermissionDeniedError` propagates as a real permission error.

**Superseded by Task 7c:** since every call already runs a fresh browser + Picker round (see Task 6b), the token cache this stage's `force_reauth`/re-auth-retry logic exists to recover from was removed entirely — there's no more stale-cached-token scenario to guard against. See Task 7c and system design §7.1 for the current behavior.
