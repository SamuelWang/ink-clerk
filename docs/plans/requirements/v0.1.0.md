# Requirements — v0.1.0 Claude Plug-in

## 1. Overview

### 1.1 Milestone Goal

v0.1.0 delivers the Claude Plug-in: a locally-running MCP server and a set of Claude Code skills
that give Claude access to InkClerk projects and documents on the user's machine.

The plug-in implements InkClerk's core UX contract in the Claude environment:
> AI edits land as drafts → user reviews diff → user accepts → draft becomes the formal version.

### 1.2 Supported Environments

| Environment | MCP Server | Skills |
|---|---|---|
| Claude Desktop App | ✓ | ✓ |
| Claude Code (CLI / IDE extension) | ✓ | ✓ |
| Claude Web App (claude.ai) | ✗ | ✗ |

Skills are exposed as **MCP Prompts** in the Desktop App; Claude Code receives them as namespaced slash commands defined in `skills/<name>/SKILL.md`.

The plug-in requires local filesystem access. The Claude Web App cannot access the local drive
and is explicitly out of scope for this milestone.

### 1.3 Deliverables

1. Claude Plug-in sub-project initialized (`claude-plug-in/`)
2. MCP Server tools, resources, and prompts completed
3. Claude Code skills completed
4. Client-side Google sign-in/Picker page (`apps/web`) and import-session relay (`apps/web-api`) deployed
5. Google Docs import as a Markdown document completed

`apps/web-api` is scaffolded in v0.1.0 solely to host the import-session relay (§5.1) — it never talks to Google and never holds a Google client secret. Its other planned routers (`/projects`, `/files`, `/drafts`, `/ai`) are out of scope until Milestone 3 (see §7).

### 2.2 MCP Server Dependencies (`pyproject.toml`)

| Package | Purpose |
|---|---|
| `mcp` | Official MCP Python SDK |
| `uuid7` | UUID v7 generation (time-ordered) |
| `google-api-python-client` | Google Docs API v1 / Drive API export |
| `markdownify` | HTML → Markdown conversion |
| `diff-match-patch` | Unified diff computation for `get_diff` |

Runtime: Python ≥ 3.11. Package manager: `uv`.

Start command: `cd claude-plug-in/mcp && uv run python src/main.py`

`google-auth-oauthlib` is **not** an MCP server dependency — no part of this system does an authorization-code exchange or holds a Google client secret (§2.3, §5.1). The browser obtains the access token directly from Google; the MCP server depends on `google-auth` (to wrap the bare access token in a `Credentials` object) instead.

### 2.3 Web API Dependencies (`apps/web-api/pyproject.toml`)

| Package | Purpose |
|---|---|
| `fastapi` | Web framework for the import-session relay router |
| `uvicorn` | ASGI server |

No Google dependency: this service never talks to Google, so it needs neither `google-auth-oauthlib` nor `httpx` as a runtime dependency (`httpx` remains a dev-only dependency, required by `starlette.testclient` for tests).

Runtime: Python ≥ 3.11. Package manager: `uv`.

Start command (local dev): `cd apps/web-api && uv run uvicorn src.main:app --reload`

## 3. MCP Server

### 3.1 Tools

Each tool name, its inputs, outputs, behavior, MCP annotations, and error conditions are
specified below. Tool inputs identify documents by **`project_name`** (display name, resolved
case-insensitively under `~/Documents/InkClerk/`) and **`doc_path`** (path relative to the
project root, e.g. `q3/notes.md`). Output fields may return absolute paths for display purposes.

---

#### `create_project`

Creates a new InkClerk project folder under `~/Documents/InkClerk/` and initializes
`.inkclerk/project.json`.

**Annotation:** none (additive)

**Inputs:**

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | yes | Human display name for the project (e.g., `"Meeting Notes"`) |
| `description` | string | no | Optional description; defaults to `""` |

**Outputs:**

| Field | Type | Description |
|---|---|---|
| `project_id` | string | UUID v7 assigned to this project |
| `project_path` | string | Absolute path to the created project folder (e.g., `/home/user/Documents/InkClerk/meeting-notes/`) |
| `project_json_path` | string | Absolute path to the created `project.json` |

**Behavior:**
- Derives a folder slug from `name`: lowercase, runs of whitespace and non-alphanumeric characters
  replaced by a single hyphen, leading/trailing hyphens stripped
  (e.g., `"Meeting Notes"` → `meeting-notes`).
- Creates `~/Documents/InkClerk/{slug}/` and `.inkclerk/` inside it.
- Writes `project.json` with `version: 1`, a new UUID v7 `id`, `name`, `description`,
  `created`, and `lastModified` set to the current UTC timestamp.

**Errors:**
- `FOLDER_ALREADY_EXISTS` — `~/Documents/InkClerk/{slug}/` already exists.

---

#### `list_projects`

Discovers all InkClerk projects (folders containing `.inkclerk/project.json`) under a root path.

**Annotation:** `readOnlyHint: true`

**Inputs:** None.

**Outputs:**

Array of project summaries:

| Field | Type | Description |
|---|---|---|
| `path` | string | Absolute path to the project folder |
| `id` | string | Project UUID v7 |
| `name` | string | Project display name |
| `description` | string | Project description |
| `last_modified` | string | ISO 8601 UTC timestamp from `project.json` |

**Behavior:**
- Scans the immediate children of `~/Documents/InkClerk/`, collecting every folder that contains `.inkclerk/project.json`. Projects are always top-level directories; no recursive descent is performed.
- Reads each `project.json` to populate the summary fields.

---

#### `delete_project`

Deletes an InkClerk project and all files within it.

**Annotation:** `destructiveHint: true`

**Inputs:**

| Field | Type | Required | Description |
|---|---|---|---|
| `project_name` | string | yes | Display name of the InkClerk project (case-insensitive match) |

**Outputs:**

| Field | Type | Description |
|---|---|---|
| `project_id` | string | UUID v7 of the deleted project (read from `project.json` before deletion) |
| `deleted_path` | string | Absolute path to the project folder that was deleted |

**Behavior:**
1. Resolves `project_name` to a project folder by scanning `~/Documents/InkClerk/` for
   subdirectories containing `.inkclerk/project.json` whose `name` field matches
   (case-insensitive).
2. Reads `project.json` to capture `project_id`.
3. **Prompts the user for explicit confirmation** before proceeding
   (e.g., `"This will permanently delete project '{name}' and all its files. Type the project name to confirm:"`).
   Does not proceed without a confirmation response that matches the project name exactly.
4. If confirmed: recursively deletes the entire project directory, including all documents,
   asset folders, drafts, and the `.inkclerk/` metadata directory, using `shutil.rmtree`.
5. Returns the captured `project_id` and `deleted_path`.

**Errors:**
- `PROJECT_NOT_FOUND` — no project named `project_name` exists under `~/Documents/InkClerk/`.
- `AMBIGUOUS_PROJECT_NAME` — multiple projects share the same name (case-insensitive).

---

#### `rename_project`

Renames an InkClerk project — updates the display name in `project.json` and renames the project
folder to the slug derived from the new name.

**Annotation:** `destructiveHint: true`

**Inputs:**

| Field | Type | Required | Description |
|---|---|---|---|
| `project_name` | string | yes | Current display name of the project (case-insensitive match) |
| `new_name` | string | yes | New display name for the project |

**Outputs:**

| Field | Type | Description |
|---|---|---|
| `project_id` | string | UUID v7 of the renamed project |
| `old_path` | string | Absolute path to the project folder before renaming |
| `new_path` | string | Absolute path to the project folder after renaming |
| `new_name` | string | The new display name as stored in `project.json` |

**Behavior:**
- Resolves `project_name` case-insensitively.
- Derives a new folder slug from `new_name` using the same `slugify` rules as `create_project`.
- Renames the project folder from the old slug to the new slug via `Path.rename`.
- Updates `name` and `lastModified` in `.inkclerk/project.json`.

**Errors:**
- `PROJECT_NOT_FOUND` — no project named `project_name` exists under `~/Documents/InkClerk/`.
- `AMBIGUOUS_PROJECT_NAME` — multiple projects share the same name (case-insensitive).
- `FOLDER_ALREADY_EXISTS` — `~/Documents/InkClerk/{new_slug}/` already exists (name collision with another project or directory).

#### `rename_document`

Renames a document within a project, moving its pending draft and assets folder if they exist.

**Annotation:** `destructiveHint: true`

**Inputs:**

| Field | Type | Required | Description |
|---|---|---|---|
| `project_name` | string | yes | Display name of the InkClerk project (case-insensitive match) |
| `doc_path` | string | yes | Current path to the `.md` file relative to the project root (e.g. `q3/notes.md`) |
| `new_filename` | string | yes | New filename without extension (e.g. `q3-notes`) |

**Outputs:**

| Field | Type | Description |
|---|---|---|
| `old_doc_path` | string | Absolute path to the document before renaming |
| `new_doc_path` | string | Absolute path to the document after renaming |
| `draft_moved` | boolean | Whether a pending draft was also moved |
| `assets_moved` | boolean | Whether a sibling assets folder was also renamed |

**Behavior:**
1. Resolves project and document.
2. Renames `{old_stem}.md` → `{new_filename}.md` within the same directory.
3. If a draft exists at `.inkclerk/drafts/<old-rel>.md`, moves it to `.inkclerk/drafts/<new-rel>.md`.
4. If a sibling assets folder `{old_stem}-assets/` exists, renames it to `{new_filename}-assets/`.
5. If the assets folder was renamed, rewrites all occurrences of `./{old_stem}-assets/` in the document body to `./{new_filename}-assets/`, preserving the original frontmatter.
6. Updates `lastModified` in the document's frontmatter.

**Errors:**
- `PROJECT_NOT_FOUND` — no project named `project_name` exists under `~/Documents/InkClerk/`.
- `AMBIGUOUS_PROJECT_NAME` — multiple projects share the same name (case-insensitive).
- `FILE_NOT_FOUND` — `doc_path` does not exist within the project.
- `FILE_ALREADY_EXISTS` — a file named `{new_filename}.md` already exists in the same directory.

#### `move_document`

Moves a document to a new location within the same project or to a different project, relocating its pending draft and assets folder if they exist.

**Annotation:** none (modifying but not irreversibly destructive)

**Inputs:**

| Field | Type | Required | Description |
|---|---|---|---|
| `project_name` | string | yes | Display name of the source InkClerk project (case-insensitive match) |
| `doc_path` | string | yes | Current path to the `.md` file relative to the source project root (e.g. `q3/notes.md`) |
| `destination_project_name` | string | no | Display name of the destination project (case-insensitive match). Defaults to the same project if omitted. |
| `destination_path` | string | yes | New path relative to the destination project root, including filename (e.g. `archive/notes.md`) |

**Outputs:**

| Field | Type | Description |
|---|---|---|
| `old_doc_path` | string | Absolute path to the document before the move |
| `new_doc_path` | string | Absolute path to the document after the move |
| `draft_moved` | boolean | Whether a pending draft was also moved |
| `assets_moved` | boolean | Whether a sibling assets folder was also moved |

**Behavior:**
1. Resolves source project and document.
2. Resolves destination project (same as source if `destination_project_name` is omitted).
3. Computes the absolute destination path; verifies it is under the destination project root (prevents `..` traversal).
4. If the destination file already exists, raises `FILE_ALREADY_EXISTS`.
5. Creates intermediate destination directories if needed.
6. Moves the document file (using `shutil.move` to handle cross-device moves).
7. If a draft exists at `<src-project>/.inkclerk/drafts/<doc_path>`, moves it to `<dst-project>/.inkclerk/drafts/<destination_path>`, creating intermediate directories as needed.
8. If a sibling assets folder `{old_stem}-assets/` exists next to the source document, moves it to `{new_stem}-assets/` next to the new document location.
9. If the assets folder was moved and the stem changed, rewrites all occurrences of `./{old_stem}-assets/` in the document body to `./{new_stem}-assets/`, preserving the original frontmatter.
10. Updates `lastModified` in the document's frontmatter.

**Errors:**
- `PROJECT_NOT_FOUND` — source or destination project not found under `~/Documents/InkClerk/`.
- `AMBIGUOUS_PROJECT_NAME` — source or destination project name matches multiple projects.
- `FILE_NOT_FOUND` — `doc_path` does not exist within the source project.
- `FILE_ALREADY_EXISTS` — `destination_path` already exists in the destination project.

- `AMBIGUOUS_PROJECT_NAME` — multiple projects share the same name (case-insensitive).

#### `import_google_doc`

Fetches a Google Doc, converts it to InkClerk Markdown, and creates a new document in a project.
See §5 for the full conversion specification.

**Annotation:** none (additive)

**Inputs:**

| Field | Type | Required | Description |
|---|---|---|---|
| `project_name` | string | yes | Display name of the destination InkClerk project (case-insensitive match) |
| `filename` | string | no | Output filename without extension. Defaults to the Google Doc title (slugified). |
| `subdirectory` | string | no | Relative subdirectory within the project. Defaults to project root. |

There is no document URL/ID input — every call opens a browser window where the user signs in
with Google and picks the target document via Google's own Picker (§5.1); the picked `file_id` is
what gets imported.

**Outputs:**

| Field | Type | Description |
|---|---|---|
| `doc_path` | string | Absolute path to the created `.md` file |
| `doc_id` | string | UUID v7 assigned to the new document |
| `dropped_styles` | array of strings | Always `[]`. Visual styles (color, font, underline) are preserved as inline HTML rather than dropped. |

**Errors:**
- `PROJECT_NOT_FOUND` — no project named `project_name` exists under `~/Documents/InkClerk/`.
- `AMBIGUOUS_PROJECT_NAME` — multiple projects share the same name (case-insensitive).
- `FILE_ALREADY_EXISTS` — the target `.md` file already exists.
- `AUTH_REQUIRED` — the browser sign-in + Picker round did not complete (missing configuration, it timed out, or the session expired before the user finished); user must retry.
- `GOOGLE_API_ERROR` — Google Docs API returned an error (message included).
- `PERMISSION_DENIED` — the authenticated user does not have read access to the Google Doc.

## 4. Claude Code Skills

Skills are `SKILL.md` files in `claude-plug-in/skills/<name>/` subdirectories that define Claude Code slash commands. Each skill is invoked with its plugin namespace prefix (e.g. `/inkclerk:import-google-doc`). Each skill file specifies the description, and the step-by-step instructions Claude follows when the skill is invoked. Each skill also has a corresponding MCP Prompt (same name, snake_case) registered in `prompts/prompts.py` for Claude Desktop App users.

### 4.1 `/inkclerk:import-google-doc`

**File:** `skills/import-google-doc/SKILL.md`

**Purpose:** Import a Google Doc into an InkClerk project as a Markdown document.

**Flow:**
1. Ask the user for the target project path (or resolve from current working directory if inside
   an InkClerk project). There is no Google Doc URL/ID to collect — calling `import_google_doc`
   always opens a browser window where the user signs in with Google and picks the document via
   the Google Picker.
2. Optionally ask for an output filename; default to the Google Doc title.
3. Call `import_google_doc`.
4. Report the created document path.

---

### 4.2 `/inkclerk:propose-edit`

**File:** `skills/propose-edit/SKILL.md`

**Purpose:** Propose an AI-generated edit to the current document and write it as a draft.

**Flow:**
1. Identify the target document (current open file, or ask the user for a path).
2. Read the document content via `read_document`.
3. Ask the user what change they want (if not provided as an argument).
4. Generate the revised Markdown content.
5. Call `propose_edit`.
6. If the response includes `overwritten: true`, surface a warning:
   "A previous draft was replaced."
7. Call `get_diff` and display the unified diff in a fenced `diff` code block.
8. Prompt the user to run `/inkclerk:accept-draft` to accept or `/inkclerk:reject-draft` to discard.

---

### 4.3 `/inkclerk:accept-draft`

**File:** `skills/accept-draft/SKILL.md`

**Purpose:** Accept the pending draft for the current document, making it the formal version.

**Flow:**
1. Identify the target document (current open file, or ask the user for a path).
2. Call `get_diff` and show the diff to the user for final review.
3. **Ask for confirmation:** "Accept this draft? This will overwrite the formal document. (yes/no)"
4. If confirmed, call `accept_draft`.
5. Report success: "Draft accepted. The formal document has been updated."
6. If the user says no, report: "Cancelled. The draft was not accepted."

---

### 4.4 `/inkclerk:reject-draft`

**File:** `skills/reject-draft/SKILL.md`

**Purpose:** Discard the pending draft for the current document without modifying the formal version.

**Flow:**
1. Identify the target document (current open file, or ask the user for a path).
2. Call `get_draft` to confirm a draft exists and show the user what will be discarded.
3. Ask for confirmation: "Discard this draft? The formal document will remain unchanged. (yes/no)"
4. If confirmed, call `reject_draft`.
5. Report success: "Draft discarded. The formal document was not changed."
6. If the user says no, report: "Cancelled. The draft was not discarded."

## 5. Google Docs Import — Conversion Specification

### 5.1 Authentication

Sign-in happens entirely client-side, in the browser (`apps/web`'s `/import/google-doc` page,
deployed on Render), using Google Identity Services — no Google Cloud OAuth client secret exists
anywhere in this system, and no user registers their own. `apps/web-api` (also on Render) relays
the already-obtained result to the local MCP server, which has no public endpoint of its own for
the browser to reach.

- Uses OAuth 2.0 with the Drive API v3 per-file scope (`drive.file`), which only grants access to
  documents the user explicitly selects through a Google Picker — not blanket read access to the
  user's Drive. This is a *sensitive* scope rather than a *restricted* one, avoiding the CASA
  security assessment and demo-video requirement that `drive.readonly` (the scope used prior to
  v0.1.0) would have needed for production verification.
- The Google OAuth client (ID only — "Web application" type, no client secret) and a separate
  Picker API key are a one-time, maintainer-level setup: created once in Google Cloud Console and
  embedded directly in `apps/web`'s browser bundle as build-time env vars
  (`VITE_GOOGLE_CLIENT_ID`, `VITE_GOOGLE_PICKER_API_KEY`). Both are meant to be public — Google's
  client-side token model for web apps doesn't use a client secret at all.
- Each time `import_google_doc` runs, the MCP server opens the system browser to `apps/web`'s
  `/import/google-doc` page and polls `apps/web-api` for the result. That page requests an access
  token directly from Google (`google.accounts.oauth2.initTokenClient`, client-side, no redirect)
  and then drives the Google Picker so the user picks the target document — see system design
  §7.1 and §7.5 for the full sequence.
- No access token is cached to disk, and no refresh token is ever issued (Google's client-side
  token model never issues one). Because `drive.file` access is granted per picked file, and
  picking a file through the Picker is how the caller learns which document to import in the
  first place, every call needs its own fresh browser + Picker round regardless of whether an
  earlier token would still be time-valid — a cache would rarely save anything.

### 5.2 Fetch

- Uses the `file_id` returned by the Picker (§5.1) as the document ID — there is no URL/ID to
  parse.
- Exports the document as HTML via the Google Drive API export endpoint
  (`/files/{id}/export?mimeType=text/html`).

### 5.3 Style Mapping

| Source style | Markdown output |
|---|---|
| Bold | `**text**` |
| Italic | `*text*` |
| Strikethrough | `~~text~~` |
| Heading 1–6 | `#` through `######` |
| Ordered list | `1. item` |
| Unordered list | `- item` |
| Blockquote | `> text` |
| Inline code | `` `code` `` |
| Code block | ```` ```\ncode\n``` ```` |
| Table | GFM table syntax |
| Hyperlink | `[text](url)` |
| Inline image | `![alt](./filename-assets/image.ext)` |
| Horizontal rule | `---` |
| Font family | `<span style="font-family: …;">text</span>` |
| Font size (non-heading) | `<span style="font-size: …;">text</span>` |
| Text color | `<span style="color: …;">text</span>` |
| Background/highlight color | `<span style="background-color: …;">text</span>` |
| Underline (via `<span>`) | `<span style="text-decoration: underline;">text</span>` |
| Underline (via `<u>`) | `<u>text</u>` |

Visual styles with no native Markdown equivalent are preserved as inline HTML so they render correctly in file-based markdown viewers (VS Code, Obsidian, GitHub). They will not display visually in Claude's chat UI, which strips inline style attributes for security.

### 5.4 Image Handling

- Each inline image in the Google Doc is downloaded from its Google-hosted URL.
- Saved to `{output_filename}-assets/{original-filename}` (siblings of the `.md` file).
- Asset folder is created lazily only if images are present.
- The Markdown image reference uses `./`-prefixed relative paths.
- Unicode/CJK filenames: raw Unicode on disk; percent-encoded in the `.md` source.

### 5.5 Document Creation

- InkClerk frontmatter is injected at the top of the file:
  ```markdown
  ---
  id: <uuid-v7>
  created: <utc-iso8601>
  lastModified: <utc-iso8601>
  ---
  ```
- `created` and `lastModified` are both set to the import timestamp.
- The output filename defaults to the Google Doc title, slugified (lowercase, spaces → hyphens,
  non-ASCII stripped from the slug but preserved in the document body).

## 6. Non-functional Requirements

| Requirement | Specification |
|---|---|
| Python version | ≥ 3.11 |
| Package manager | `uv` |
| MCP SDK | `mcp` (official Python SDK) |
| Google credentials | No client secret exists anywhere in this system. The OAuth client ID and Picker API key are public, embedded as build-time env vars in `apps/web`'s browser bundle. No access token is persisted anywhere — each import runs its own browser sign-in + Picker round |
| Web app / web API URLs | `INKCLERK_WEB_APP_URL` and `INKCLERK_WEB_API_URL` env vars on the MCP server (set via `claude-plug-in/.mcp.json`'s `env` block for plugin launches); point at the deployed `apps/web` and `apps/web-api` Render URLs respectively |
| Unicode filenames | All file I/O must handle raw Unicode on disk; percent-encode references in Markdown |
| CJK filename limit | Truncation logic must account for 255-byte filesystem limit (~85 CJK characters) |
| MCP start command | `cd claude-plug-in/mcp && uv run python src/main.py` |
| Error format | All tool errors return a structured payload: `{ "error": "<CODE>", "message": "..." }` |
